## 0. 用語

**【決定】** 「Focus」という語はここでは使わない。frame.md の Focus（Exhibit の詳細ページ、`/focus/:slug` への遷移）とは別概念で、
Icon クリックで **index 上にその場展開する**（別ページへは飛ばない）。

この状態の名称は「**Emanation**」に決定。
「俺という存在（へのへのん）がまずあり、その世界観の一部を切り取って出力する」というイメージから、
「存在から滲み出るもの」を意味するこの語を選んだ。中心の光る球が文字通り光を放っている絵とも重なる。
Focus / Gallery / Icon 同様、docs（SSOT）への正式な記載はユーザー自身が行う。

## 1. Icon — へのへのん画像

- **【決定】** 現行の ASCII フェイス（`へ　へ / の　の / 　ん`）を、へのへのん画像（ランダムに 1 枚）に差し替える
- **【決定】** アニメーション（まばたき・傾き）は**保留**。今回は静止画のみ
- 素材: 本セッション内で用意可能（枚数・配置は着手時に確定 → `TBD-asset`）

- **【決定】** Gallery の Icon（`ExhibitIcon` 経由）は画面外なので `IntersectionObserver` で遅延 import しているが、
  Introduction の Icon は常にファーストビューにあるため、その遅延パターンは踏襲しない（最初から読み込む）
- **【決定】** ランダム選出は「挨拶/about」の判定（`page.ts` の `browser &&` ガード）と同じ理由で、**クライアント側のみで確定**させる。
  プリレンダ／SSR 時は固定の 1 枚（先頭）を出し、hydration 後にランダムへ差し替える（`about` 判定と同じ「揺れない初期表示」方針）
- **【決定】** 画像アセットの指定は、**「Icon のランダム候補」と「フォルダ内の画像一覧」を明確に分けて管理する**。
  フォルダを glob して両方を兼用させない（§2 の「へのへのアイコンズ」用と役割が混ざらないようにするため）

## 2. Emanation — 3D 浮遊シーン

- **【決定】** トリガーは Icon クリック。**index 上でその場展開**（別ページ遷移なし）
- **【決定】** 中心に光る球がある
- **【決定】** 周囲を漂う浮遊オブジェクトの内訳:
  - **skills / 資格** → 浮遊ワード
  - **展示に乗り切れなかった作品**（例: `exhibits.ts` に現在コメントアウトされている `make-with-puppet`）→ 浮遊オブジェクト
  - **へのへのアイコンズ**（Icon で使う画像のバリエーション）→ 浮遊オブジェクト
- **【決定】** 操作は**ドラッグのみ**。クリックによるインタラクションは**今回一切なし**（v1 では全オブジェクト非クリッカブル）
- **【決定】** 自己紹介文・主要リンク（X / GitHub / More）は Emanation に**含めない**。従来通りキャプション側で扱う（→ §3）

**【決定】** ドラッグの回転主体は**カメラが球を中心に周回する**方式。
狙う感覚は「球を中心とした世界を、訪問者が外から見て回る」。
three.js の定番実装（OrbitControls 相当。zoom / pan は無効化し rotate のみ許可）にも乗れる。

**【決定】** 浮遊オブジェクトは常にカメラ正面を向く（Billboard）必要はない。自由な向きで漂ってよい。

**【決定】** 浮遊オブジェクトの表現手法は、v1 は種類を問わず**canvas / 画像テクスチャを貼った平面**に統一する
（skills のテキストも文字ジオメトリではなく canvas に描いて焼く。作品・アイコンズの画像もそのまま平面に貼る）。
実装コストが低く、同じ仕組みで全種別を扱える。

skills だけ 3D テキストジオメトリ（英数字中心なので押し出しコストは低く、厚みが光を受けられる）にする案も出たが、
「意味を取るか実装速度を取るか」で**今回は実装速度を優先**し、3D テキスト化は将来の拡張候補として保留する。

そもそも「何を配置するか」自体の具体（どの skill を出すか等）もまだ固まっていないため、
**最初の一歩は仮の（tmp な）オブジェクトを漂わせるだけでもよい**——実データの確定を待たずに
「光る球＋浮遊＋ドラッグ回転」の骨格を先に動かして確かめる、という進め方を許容する。

**【決定】** three.js 本体とシーン一式は、**ファーストビュー表示後のアイドル時間（`requestIdleCallback` 等）に先読みしておき、
間に合わない分は Emanation の展開トランジションの尺で隠す**。frame.md「トランジションこそが本サイトの体験のキモ」に沿い、
GlobeXplore のワープ演出と同じ考え方（読み込み待ちを演出で吸収する）を踏襲する。
初期バンドルには含めない（他の 3D 展示と同様、Introduction が常時ファーストビューでも three.js 自体は遅延させる）。

## 3. キャプション／リンク — 変更なし

- **【決定】** 挨拶⇄タイトルの text morph、および `intro-links`（X / GitHub / More）は**現行のまま触らない**
- **【決定】** これらは Emanation（§2）の対象に含めない

「リンクはキャプションで」＝リンクを Emanation シーンに持ち込まず**今の場所に残す**という意味であり、
キャプションカードの DOM やスタイルを変更するという意味ではない（誤解していたため訂正）。
今回の変更は Icon（§1）と Emanation（§2）を**追加**するだけで、キャプション／リンク周りは現状を維持する。

## 4. フェーズ

| Phase | 内容 |
|---|---|
| **0** | データ整備。skills/資格リストの確定、「展示に乗り切れなかった作品」の対象確定（`make-with-puppet` のみか）、画像アセット配置 |
| **A** | Icon 差し替え（画像ランダム表示）。素材待ちにならない範囲で着手できる |
| **B** | Emanation の 3D シーン基盤（光る球＋ドラッグ回転のみ。浮遊オブジェクトなし） |
| **C** | Emanation へ浮遊オブジェクトを投入（skills → 展示 → アイコンズの順に積む） |

**着手順の提案**: A → B → C。
A はデータが薄くても独立して片付く。B で基盤（球＋回転）だけ先に手応えを作り、C で中身を積み増す。
キャプション／リンクは §3 の通り変更しないため、フェーズとして立てない。
