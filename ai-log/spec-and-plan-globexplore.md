## 2. Focus Main — 飛行映像 ＋ リンクパネル

- **【決定】** **飛んでる動画背景**
- **【決定】** **何個か切り替えられる**
- **【決定】** リンクボタンは**テキスト＋外部リンクの SVG**（「あの右上矢印と□のやつ」）
- **【決定】** **中央にボタンを 2 つ**置く。**片方が Steam、もう片方が Pro のページ**

**【提案】** Main いっぱいに動画を敷き、その中央にボタン 2 つを重ねる。

2 つの並べ方は docs の「斜めだよなー」を汲んで、横並びから少しずらして斜めに置く。
Steam（無印）と Pro の関係が伝わるよう、**同格ではなく差をつける**かは詰めどころ。

**【提案】** 切替は**自動**（各 8〜12 秒でクロスフェード）。
frame.md「**基本スクロールもクリックもナシ。何もしなくても完成している状態**」に従い、切替に操作を要求しない。
＝「何個か切り替えられる」を*自動で切り替わる*と解釈している。手動にしたいなら要修正 → `TBD-video-switch`

### 素材 — 本展示のクリティカルパス

**動画が無いと Main が成立しない。**出所が未定（Steam トレーラー / gxpro.app / 自前キャプチャ）→ `TBD-video-source`

**【決定】** **音は無し。**音声トラックごと削除する（ミュート再生なので不要）。

**【方針】** 判断基準は**リポジトリ容量ではなく体感**。容量増は受け入れるコストとして扱う。

体感を一番左右するのは動画のバイト数ではなく **poster**。背景は装飾であり、訪問者が最初に見るのは
読み込み前の静止画なので、**そこが即座に・綺麗に出ることが最優先**。逆にここが白いままだと、
動画をいくら削っても遅く感じる。

**【提案】** 目標値:

- **720p / 24〜30fps / 8〜12 秒 / ループ前提 / 3 本程度**
  全画面に敷くので、高解像度ディスプレイでは 540p の甘さが見える。
  GlobeXplore は映像の綺麗さ自体が作品の売りなので、ここをケチると展示として損をする
- **形式は素材の素性で決める**（下記「エンコード方針」）。
  クリーンなマスターがあるなら AV1 mp4 を第一ソース＋H.264 mp4 をフォールバック。
  既に圧縮済みの素材なら**再エンコードせずリマックス**
- **poster は AVIF**。ここは容量を惜しまず画質を出す（第一印象そのもの）

### 表示の段取り — poster 先出し・動画は準備でき次第

**【決定】** **静止画（poster）を必ず先に出し、動画は読み込みが完了したものだけ後から差し替わる。**

- **poster は動画の 1 フレーム目そのものにする。**差し替わる瞬間が視覚的に無音になり、フェードも要らない。
  静止していた絵がすっと動き出したように見える
- 再生開始は**バッファが十分に溜まってから**。短いループなので実質「全部読めてから始める」形になり、
  再生途中で止まらない
- クリップは**準備できたものからローテーションに加わる**。固定スケジュールで待たせない
- **モバイル（768px 未満）はローテーションに 1 本だけ加える**。回線とバッテリーの負荷だけ落とす

**【要件】** **poster 単体で展示として成立していること。**動画が来ないときの保険ではなく、それ自体が完成形。
動画は上乗せ。frame.md の「**何もしなくても完成している状態**」を、回線が細い訪問者にも成立させるため。

この段取りにより、モバイル・低速回線・`prefers-reduced-motion`・動画の取得失敗が
**すべて「poster のまま」という同じ挙動に収束する**（個別の例外処理を持たない）。

### エンコード方針 — 素材が「圧縮済み」か「クリーンなマスター」かで分かれる

**圧縮済み素材（配信サイトからの取得物など）は、再エンコードせず音声だけ落としてリマックスする。**
一度失われた信号は取り戻せず、作り直せば必ず二世代目の劣化が乗る。無劣化コピーが単純に上。

現素材（Twitter 取得・1280×720 / 30fps / 30秒 / H.264 2.24Mbps）での実測。10 秒セグメント、元 3.42MB:

| AV1 CRF | サイズ | 元との比 |
|---|---|---|
| 34 | 7.21MB | 2.11× |
| 40 | 4.58MB | 1.34× |
| 45 | 3.21MB | 0.94× |
| 50 | 2.28MB | 0.67× |

AV1 自体は正常に効いている（CRF に対して単調）。ただし**サイズで並んでも品質では並ばない**。
縮めるには劣化を受け入れるしかないので、容量を優先しない本方針ではリマックスを選ぶ。
※ CRF は品質目標でありサイズ目標ではない。低圧縮の素材に低い CRF を指定すると、
圧縮ノイズまで細部として忠実に再現しようとして**元より膨らむ**（上表の CRF 34）。

**シミュレーターから直接キャプチャしたクリーンなマスターが手に入った場合は、AV1 が本来の力を発揮する。**
そのときは AV1＋H.264 の二本立てに切り替える。

### コーデック選択の根拠（2026-08 時点の調査）

- 実測（1M+ デバイス）のデコード対応率は VP9 99.99% / H.264 99.94% / AV1 91.5% / HEVC 85.1%。
  **AV1 の穴はほぼ Apple**（ソフトウェアデコーダ未提供のため macOS Safari で約 24%・iOS Safari で約 33%）
  → AV1 単独は不可。H.264 フォールバックが要る
- AV1 のソフトウェアデコード負荷は **720p 単一ストリームなら実質問題にならない**。
  効いてくるのは 1080p 以上や同時多数再生の場合
- **WebM は使わない**。これは容量ではなく体験の問題で、iOS 17/18 に
  「1 ページに複数の WebM video 要素があると Safari がクラッシュする」報告がある。
  本設計はクロスフェード＝video 要素が同時に複数存在するので直撃する

## 3. トランジション — ワープ

- **【決定】** 「**ワープっぽいやつ**」

**【提案】** Icon 中心から**放射状に流れるスピードライン**。
dive は「加速して光に飲まれる」→ Focus が現れる、rise はその逆再生。
ドローンが宙返りしてから飛び出す動き（§1）の、そのまま延長にする。

**【提案】** 段階的に作り、途中で止められるようにする:

1. 既存の dive/rise ズームに**放射ブラー＋ホワイトフラッシュ**を足すだけの簡易版
2. 物足りなければ、流れる線を描き込んだ本気版に差し替え

片道 200〜300ms を目安（frame.md「**長すぎないこと**」）。どこまで作るかは `TBD-warp-depth`

コトハコビの蓋トランジションで「展示ごとに演出を差し替える」構造は出来ているので、そこに乗る。

## 4. ギミック — Playground（任意）

- **【決定】** 立体のロゴ＋地面の映像の中を**飛び回れる**
- **【決定】** 円形の飛行制限。近づくと **Warning!**

ただし docs §メインには「**余裕があったら Playground? なくてもいい気はする。**」ともあり、**docs 自身が揺れている**。

**【要注意】** これは frame.md の「**基本スクロールもクリックもナシ。何もしなくても完成している状態**」と正面衝突する。
Main を操作式に置き換えると Focus の約束が壊れる。

**【提案】** やるなら **Main を置き換えず、任意で入る別レイヤー**にする。
リンクパネルの脇に控えめな「操縦してみる」を置き、押したときだけ起動する。
何もしなければ §2 の完成状態のまま、という frame.md の条件を保てる。→ `TBD-playground`

**フェーズ最後に置き、切り捨て可能な位置にする。**
