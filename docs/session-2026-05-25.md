## なぜ何度も止められていたか (現時点の私なりの理解)

### 私の誤った認識

私はずっと「**機構を 1 回仕込めば、Claude がそれを CSS で opt-in/out できる**」状態を
「自由度ある実装」と思っていた。

例:
- B2 時刻シフト → `<html data-tod="...">` 属性を立てるだけ、CSS は Claude 任せ
- B4 cursor bridge → `mousemove` listener、`--mx`/`--my` を立てるだけ、使用は Claude 任せ
- D1 View Transitions → `<ClientRouter />` 入れるだけ、演出は CSS 自由
- B3 favicon 色追従 → favicon SVG に theme 色 inject、Claude 関与なしで日替わり

これらは「Claude が CSS で取捨選択できる」から自由度ある、と私は思っていた。

### ユーザーの実際の境界

ユーザーの基準はそれより一段厳しい:

> **「サイト本体に常駐する機構そのものが、テーマ生成プロセスの外で決定されている」=詰め込み**

つまり:

- `data-tod` 属性は **常に立つ** (Claude の今日の判断と無関係に立つ)
- `mousemove` listener は **常に動く** (今日のテーマがカーソル演出を望むかと無関係に動く)
- `<ClientRouter />` は **全ページ遷移を SPA 化する** (Claude が opt-in できない)
- favicon の色追従は **常に発動する** (Claude が「今日は favicon 変えたくない」と決められない)

これらの機構の "存在" 自体が、毎日の判断を経ない常駐の決定。
たとえ Claude が CSS で「使わない」を選べても、機構そのものはサイト体験の一部として常駐している。

### なぜ B1 だけ通ったか

OGP 画像生成は:

- **サイト本体の表示には一切影響しない** (シェア時にしか登場しない)
- 機構 (`build-og.ts`) は `dist/` にだけ書き込み、ユーザーが見るページに常駐しない
- Claude が日次で生成する判断と歩調が合う (失敗時は前日のまま、Claude のセンスが反映)

つまり境界線は:

> **常駐の機構が "ユーザーが見るサイト体験" に影響するか否か**

OGP は影響しない (シェア体験の副作用) → 通る。
他は影響する (サイト本体に常駐) → 詰め込み判定 → catalog 整理が必要。

### カタログ整理が「もうちょっとちゃんとしたい」と言われる理由 (推測)

「inspiration md を渡せば Claude が選んでくれる」だけでは不足で、
**Claude の日次判断が、機構の存在自体を on/off できるレベル** にしないと適切性が保てない。

例えば time-of-day 機構を Claude が「今日は時刻分岐しない」と決められるなら OK
(その日は属性が立たない、bridge が動かない、等)。

これは単なる md 充実より深い設計が要る。私はまだそこを正しく理解しきれてない可能性がある。

## 私の改善点 (次セッション以降)

1. **「機構を仕込めば自由」を疑う癖** — 機構の存在自体が常駐の決定であることを認識する
2. **提案前に問う** — 「これは Claude の日次判断にどう関与するか? 機構そのものが
   テーマと無関係に常駐するなら、それは詰め込みでは?」
3. **`always-on` インフラを軽率に提案しない** — 体験の常駐物は最小に
4. **ユーザーの "ダメですね" は深く聞く** — 私の認識のズレを示すサイン
5. **「断片的情報で安直に決めない」(ブランドマーク事案)** — 「これだ」と早合点せず、
   過去資産・既存判断の蓄積を先に確認する
6. **過去資産の探索は浅くせず** — `git ls-tree archive/*` だけでなく全コミット履歴も視野に
